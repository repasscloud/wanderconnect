# Coded media review — Q97

DEFAULT implementation,2 November2026. Presentation/reporting reason codes do not change D178 eligibility, screening, staff permissions, conflict exclusions, evidence preservation or the existing escalation path. Adult-media policy remains deferred.

`MediaDecision` adds optional `reasonCode` alongside existing `decision`/`reason` (private terminal-decision notes, up to500 characters). Codes are stable and decision-bound: approved reasons for approve, ordinary violations for reject, serious/uncertain safety concerns for escalate. `REJECT_OTHER` requires substantive notes on the server. Unknown/mismatched codes refuse400. Coded approvals omit notes: approval can later be superseded, and a retained private review-note history is not yet implemented. Reject/escalate notes use the existing final-review field. Legacy approval notes retain the old ignored behavior; the server never silently accepts coded approval notes. Existing clients that omit the new property remain compatible and are labelled `LEGACY_APPROVE`, `LEGACY_REJECT` or `LEGACY_ESCALATE`; the server does not invent a selected reason.

The existing lifecycle lease and source-save transaction commit the latest human-review code in nullable `MediaItem.ReviewReasonCode`, private `ReviewReason` notes and an existing audit entry (`media.reviewed`, machine code only) with the actual state transition. Older rows remain null; no backfill or policy finding is fabricated. Code counts use retained coded audit entries over the last30 days, including distinct uncategorised legacy-client labels; older uncoded decisions are excluded. This is a bounded operational view, not a statutory completeness claim. No notes enter audit details or member projections.

The Admin queue supplies reason metadata and counts. Routine queue access records the factual queue-review purpose automatically; a separate reveal POST records access again before unblurring. Case-specific purpose/evidence access is unchanged. Approve/reject/escalate remain explicit actions; escalation does not require a definitive finding. No media is visible before deliberate access, and blocked media stays inaccessible.

The additive nullable column uses the existing MediaItems lifecycle/retention and preservation boundaries. The upgrade only adds a nullable column; no installed database was migrated. No new project/service or retained review table is introduced. Case-specific legacy forms retain their explicit purpose/free-text behavior and are honestly classified as legacy clients; consistent coded controls there remain a follow-up. Retained private approval-note history is also a remaining dependency, rather than creating ungoverned retained notes. Local acceptance uses generated canvas JPEGs and disposable resources only; no sensitive screenshot or adult material is needed.

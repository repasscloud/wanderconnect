## Disposal authority

Account state changes use a short per-account PostgreSQL advisory lease. Screening/publication uses a separate media lease. Coverage changes take the global preservation barrier exclusively; source destruction, capture and ordinary committed writes take it shared. Case and hold mutexes serialize retention decisions and evidence numbering/custody commits across processes. Order is account state, media when needed, preservation barrier, case/hold mutex. Shared authority is never upgraded to exclusive. Conversation row locks follow the preservation barrier.

Disposal rechecks live holds under authority, commits before releasing it, and retries interrupted due work. No trustworthy hold status means no disposal. Case snapshots retain explicit media references; unreadable legacy references fail closed. Released retained copies remain accessible only through existing legal-role, conflict, purpose, elevation, approval and expiring one-use export controls. Known-content media is never rendered.

## Operations and remaining evidence

`retention purge` reconciles explicit historical staff associations, coordinates case, account, message and media expiry, then expires eligible minimal conflict records. `staff conflicts reconcile` independently materialises authoritative current/audited links and runs the same guarded expiry. `retention purge --case <id>` restricts case/copy disposal to one case; `retention purge --account <id>` restricts review/copy expiry to the named member’s cases and known copies. Case scans use keyset paging so held or unresolved batches cannot starve later eligible records. `accounts purge <id>` restricts account finalization and media sweeping to one account. The hosted worker runs hourly; Development requires explicit opt-in. Counts and machine reasons are logged; content is not.

## Released operational groups (D260 DEFAULT)

A released hold's reason/conditions/release notes, scopes, whole custody chain, export purposes/corrections/redactions and approval/disclosure/transfer records form one operational retention group. Retain until the later of applicable review/police windows and24 calendar months after its latest recorded activity. Police/disclosure groups instead use84 calendar months, including the latest transfer receipt. These are proposed implementation defaults subject to57; a recent export/receipt cannot be erased by backdating only the original case closure.

The hourly/one-shot coordinator runs this expiry before case disposal. Current source provenance remains until the group expires; it is not treated as indefinite permission to retain detailed case content. Copies/private media must already be disposed under their own lawful rules. Active/overlapping obligations, unknown source dates/membership, missing case/police provenance and unavailable hold status refuse group erasure. A successful transaction removes the entire chain and related free text atomically, retaining an ids-only completion audit. It never deletes a chain link and leaves the remainder looking intact. Ordinary case/police record expiry can then continue.

Unversioned legacy identifier markers have a counts-only import gate (`bans legacy-status`), not a guessed cryptographic migration. Unknown original ownership/key/case remains a review requirement. Remaining118 work includes global sensitive-access-chain/other operational minimisation and encrypted isolated backup expiry/restore reconciliation; this slice does not close118.

## Global audit and residual operational metadata (D262 DEFAULT)

Restricted-access entries and ordinary operational audit metadata have a24-calendar-month schedule. A verified oldest prefix advances one minimal chain checkpoint (sequence/hash/through-time/disposal-time, no actor, route or content), preserving all surviving hashes and continuity after an empty log. Ordinary update/delete/truncate remains refused; expiry uses a validated bounded database operation under preservation and chain authority. The read window shares chain authority with append/expiry. Null/future purge authority is refused, and UTC calendar calculations are explicit.

Any retained hold group (including released groups awaiting lawful expiry), independently retained copies, earlier retained review/police sources and unclosed/recent security incidents defer disposal. Query events do not record result sets, so the safe default conservatively pins prefixes while potentially relevant source records remain; do not claim every unrelated row expires immediately at24 months. Old grant purpose expires after its final expiry/revocation plus24 months only once retained access-log and email-retirement references permit it. Closed, assessed security incidents use24 months after their latest closure/assessment/containment, subject to source/preservation obligations. Ordinary operational audit rows expire after24 months with the same source safeguards; explicit staff-conflict history remains governed by D235. Completion is recorded minimally. These proposed periods remain subject to57. Hosted runtime roles must receive only the required expiry-function execution, never checkpoint writes; database owners can alter schema and are outside this integrity boundary.

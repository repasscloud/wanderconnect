# Q108 — Independent mode photos and shared library

CONFIRMED D293 ([owner answer](https://github.com/repasscloud/wanderconnect/issues/150#issuecomment-6572392572), 2 November 2026) supersedes D175's shared main photo: every mode has an explicitly selected optional main. A missing main uses a placeholder and does not prevent discovery. Mode totals include the main: Free 8, Plus 16, Premium 24. Downgrades keep library objects and gallery order, hiding the tail without deleting it.

DEFAULT library capacity 60 implements the owner's 60-unless-excessive-overhead answer: one stored library object can be referenced by any number of mode placements; neither mode assignment nor main selection copies image bytes. This is an architectural storage observation, not a measured hosting-cost acceptance.

## Implementation

`MediaPlacement.IsMain` records an explicit main within a mode gallery. A partial unique index permits at most one main per member/mode. The nullable `PhotoPlacementUpdate.MainMediaId` names a photo in that gallery; null means no main. Legacy global `main` is no longer a valid placement scope. `MyPhotosView.Main` remains present as null for wire compatibility; `Mains` exposes independent selections, while `Modes` includes all retained assignments and MaxPerMode is the current tier allowance.

Migration `20261102120000_ModeMainPhotos` preserves all existing objects and placements with `IsMain=false`. It never assigns a historic shared main to any mode and does not rewrite previous evidence snapshots. Historic global rows remain dormant; their image stays in the member's library until explicitly deleted. Approval no longer automatically assigns a first main. Explicit screened replacement preserves existing placements and their main flags.

Profile and Explore projections use only explicitly selected mode mains. They do not fall back to the first gallery item or another mode's main. Public galleries are capped by current effective entitlement and stored order; hidden excess assignments remain stored. Reordering/removing an oversized retained gallery is allowed after downgrade, but adding beyond the current limit is refused. Existing owner/approved-status checks and screening/moderation rules remain. A media-authority recheck prevents parallel uploads from exceeding the library cap. Gallery replacement and its snapshot capture commit in one transaction.

Web uses the existing responsive thumbnail grid and one active mode at a time, with independent main/placeholder, ordering, remove-from-mode controls, visible/hidden allowance wording and library usage. Multiple file selection uploads serially with progress. Library deletion asks separately and explains removal from every mode. Native uses the same contracts, a mode selector, mode main/ordering/removal and multiple photo picking; uploads read at most the configured size plus one buffer before refusal. Theme tokens and existing typography are preserved.

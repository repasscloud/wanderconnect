# Q118 — Optional public names by mode

CONFIRMED D301 ([owner answer](https://github.com/repasscloud/wanderconnect/issues/163#issuecomment-6572853394), 2 November 2026) supersedes only D175's shared-display-name requirement. All four modes accept independent optional public names. Clearing an override uses the main public display name, never the registered/provider/verified name. One underlying account, discovery/visibility/related-pair restrictions and D143's single open conversation per pair remain.

## Implementation

`MemberMode.DisplayName` stores a nullable override, limited to the existing 40-character plain-name policy. `ModeUpdate.DisplayName` omitted/null preserves an existing override for older clients; empty/whitespace clears it. The API trims names and rejects overlong/control-character values. The own-mode DTO exposes the override; WebAssembly and native profile editors offer a labelled optional field for each mode. Existing custom main names and other mode settings remain untouched.

Profile headings, each authorised related-mode section, discovery cards, visitors, requests and connections resolve the selected mode's name. No hidden mode names are returned. Main public name remains the fallback and discovery completeness gate. Notification centre and push preview selection use request/connection mode or conversation origin; existing privacy-preview switches still apply.

New conversations store `OriginModeId` once. Web/native starts use the selected accepted mode; older clients without a mode select the earliest accepted pair connection deterministically. An explicitly selected unaccepted mode cannot start a conversation. Returning an existing conversation never changes its origin. Chat names resolve the current alias in that stored mode, so changes to unrelated aliases cannot change them. DEFAULT compatibility: historic conversations have an unknown origin and continue showing the main public name; no mode is invented from current connections.

Migration `20261102090000_ModeDisplayNames` adds nullable fields only, with no alias/provider-name backfill and no snapshot rewrite. Profile versions capture raw and effective names per mode and append changes. Exports include the member's own aliases and use only the relevant request/chat name for other people. Existing account-deletion removal of `MemberModes` removes live aliases; historical versions remain subject to the existing evidence/retention rules.

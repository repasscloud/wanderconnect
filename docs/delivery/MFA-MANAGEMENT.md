# MFA management — #193

CONFIRMED: [#193](https://github.com/repasscloud/wanderconnect/issues/193) and the staff-role issues supersede older optional-staff-MFA text. Business, Support, Trust & Safety, Admin and Legal require trusted provider MFA; Root retains its existing direct password plus OTP boundary; a recovery-code-only factor never substitutes for Root OTP. Members can enrol voluntarily or have an explicit staff-imposed requirement. Application RoleGrant records remain authoritative; Keycloak owns OTP verification, credential storage and recovery-code hashing.

## Implemented boundary

The staff home offers provider-owned authenticator replacement and conditionally recovery-code generation. Member web and native Account security open Keycloak application-initiated authenticator enrolment/replacement and, when enabled, native recovery-code generation. Swoovr never receives OTP secrets or recovery codes. Optional credential removal requires a fresh existing MFA sign-in, explicit confirmation, session revocation and provider confirmation; an imposed requirement cannot be removed by the member. A member missing required MFA retains account-security/support recovery access while normal member functions are denied.

Admin account/staff detail exposes status, credential method names, requirement controls and independent recovery. Support cannot remove stronger Trust & Safety/Admin requirements. A reset requires an elevated independent Admin, a case reference, identity-review attestation and confirmation; self/Root reset is refused and Legal protection remains. Reset removes native OTP/recovery credentials, preserves passwords and unrelated credentials, revokes sessions and preserves mandatory enrolment. Pending/uncertain provider operations remain fail closed. An attestation is an operator assertion, not automated identity verification or proof that a case exists. The approved operational procedure is OPEN [Q140/#243](QUESTIONS.md#q140--operational-identity-review-for-mfa-recovery); do not enable operational assisted recovery before that procedure is approved.

Fresh MFA elevation is separate from role and purpose authority. The API issues a one-use challenge bound to the signed subject, sid and approved client; a forced provider reauthentication must advance signed auth_time and carry trusted MFA. Only digests are persisted. DEFAULT: challenge five minutes, receipt ten minutes (`Mfa:ElevationMinutes`, bounded 1–15), three outstanding requests and ten security requests/minute. Receipts expire, cannot cross sessions/accounts/clients, and are checked against revocation. All administrative mutations (except elevation negotiation itself), identity/content/evidence access and sensitive support queues add this check for Admin/Trust & Safety. Media bytes recheck the signed current staff actor, authorised prior view and live elevation rather than trusting a copied signed link alone. Existing role, conflict, direct-session and purpose restrictions continue.

Application and native provider audit events contain actor/target identifiers, times, action/outcome and safe case/reason metadata; credential bodies/codes are excluded. Security notices go to the accepted verified email. Accepted mail submission, rejection and unknown outcome are audited separately; none establishes delivery.

## Provider configuration and acceptance

The pinned Keycloak26.8.1 provider adds native-condition overrides limited to OTP subflows. Missing mandatory OTP queues native CONFIGURE_TOTP; configured OTP enters the native factor challenge. The browser parent remains CONDITIONAL: making the native alternative-factor subflow REQUIRED executes it before a user is identified. The local-only configurator marks the staff realm mandatory, restores its conditional executions, and enables native actions. Brokered staff require equivalent post-broker challenge/assurance; this task does not configure Entra or hosted realms.

The managed launcher and legacy local launcher apply `--managed-mfa` as part of their normal realm configuration; the standalone configurator also accepts that flag. This is local configuration, not a production migration. It disables the unrestricted built-in account/account-console clients so credential deletion cannot bypass imposed MFA, while retaining application-initiated security actions. Local Compose enables Keycloak's recovery-codes feature; `Mfa:RecoveryCodesEnabled` defaults false until the operator validates native generation/use/replay and enables it. Recovery values appear only in the native provider page. No production setting, running application realm or deployment is changed by this task.

The staff directory uses a separate narrowly provisioned provider service account (`StaffAdmin` settings, #206). Hosted service-account permissions, broker assurance, sign-out propagation, mail delivery and actual web/native journeys require operator acceptance. Application migrations are additive; provider mutations cannot be rolled back atomically with PostgreSQL, so uncertain outcomes preserve the pending lock and need reconciliation. No automatic retry or credential restoration is invented.
